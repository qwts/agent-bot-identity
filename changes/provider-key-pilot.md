- With `settings.pilotProvider` set and legacy local custody off, the daemon fetches the pilot provider key from the identity service when it starts (`GET /api/daemon/provider-key`, one fresh operation per fetch, task `daemon-start`). It holds the key in memory only, never on disk, in a log or in a receipt, and drops it at once when the device is revoked. A soul whose declared provider matches gets the key in its harness environment at launch. Each fetch and each use leaves a receipt naming `provider-key-exception` and the issuance reference. No provider secret is read from a store on this host unless legacy local custody is on (owner decision D2, #1184).
