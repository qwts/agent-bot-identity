- Soul tokens v2 (#1196), opt-in: with `settings.soulTokens: "v2"` (or `AGENT_BOT_SOUL_TOKENS=v2`) on an enrolled daemon with legacy local custody off, `/v0/vouch` asks the identity service for an ES256 `soul+jwt` soul token (five minutes) and `agent-bot daemon pair-comms` sends the service's issuer and device instead of an SPKI public key — this host keeps no `vouch-key.pem` on that path. Requires the identity-service route and an agent-comms broker that accepts v2; switching a paired daemon means re-running `pair-comms`, and an existing `vouch-key.pem` can be deleted afterwards. `/v0/health` reports `soulTokens: 'v2'|'v1'` and, in v2, `vouchKeyOnHost`. Without the opt-in — the default until a later release — the v1 path is unchanged.
